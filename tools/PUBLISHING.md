# Publishing tegridydev.com

`main` contains the writing, supporting research code and website source.
`static` contains only the generated public website. GitHub Pages serves
`static` → `/ (root)` with the custom domain `tegridydev.com` and Enforce HTTPS enabled.

## Build

Use Python 3.12, uv and Node 22 on Linux, WSL or macOS. From the repository root:

```sh
uv venv --python 3.12 .venv
uv pip sync --python .venv/bin/python requirements.txt
uv run --no-project --python .venv/bin/python python -m unittest discover -s tools/tests -v
node blog/model-interpretability/what-a-model-map-can-show/test_viewer.cjs
uv run --no-project --python .venv/bin/python python tools/build.py
```

The complete site is written to `../releases/_site` only after validation succeeds.
Copy its contents into the root of the `static` branch, including `.nojekyll` and
`CNAME`. Replace the previous generated files so removed pages do not linger.
Commit the static branch and wait for its GitHub Pages deployment to finish.
Never upload the enclosing `_site`, `main` or `static` folder into the branch.

GitHub Actions checks pull requests and changes to `main`; it does not deploy or
write to either branch. Keep Pages configured to **Deploy from a branch**.
The initial release ZIP provides both branch snapshots for manual uploading.

## Update the writing

Edit Markdown in `blog/` or `research/`, then rebuild. The navigation, current-page
state, contents lists, related links, indexes, sitemap and feeds are generated
from published articles. No manual sidebar edits are needed.

Keep article IDs and folder slugs stable. Each article uses `+++` TOML metadata
with `id`, `title`, `description`, `type`, `author` and `draft = false`. Research
status is `proposal`, `implemented` or `pilot`; describe the actual scope in the
body. Use evidence-supported dates only. `related` contains published article IDs;
reading-path membership is configured in `tools/site/topics.json`.

Images and browser demos live beside their articles. Responsive image derivatives
are declared in `tools/site/images.json`; rebuild them if the source image changes.
Research tests and result records are public reproducibility material, not website
assets. The build excludes Python code, environments, caches and private files.

Production settings are in `tools/site.toml`, templates in `tools/site/templates`,
styles and scripts in `tools/site/static`. Navigation markup is generated by
`tools/navigation.py`. Cloudflare Web Analytics remains optional and disabled
unless its public site token is configured. No Google Analytics is included.

For a project-path build, pass `--base-url https://tegridydev.github.io/tegridy`.
For an isolated local preview build, pass `--preview`; production analytics and
CNAME are omitted. Generated output and execution caches do not belong in `main`.
